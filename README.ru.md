# DreyzeStore

[English](README.md) · **Русский**

DreyzeStore — открытый проект нативного каталога приложений iOS, API метаданных пакетов, формата репозиториев и веб-панели администратора. Проект развивается поэтапно. **В PHASE 3 нативный SwiftUI-клиент подключён к публичному read-only API каталога из PHASE 2.** Вход администратора и управление приложениями, передача и проверка IPA, реальные адаптеры установки и production-развёртывание остаются будущими этапами.

Обычное приложение iOS в песочнице, как правило, не может устанавливать произвольные IPA или перечислять все установленные приложения. Клиент будет сообщать об установке только после подтверждения реально доступного backend. Загрузка и проверка пакета сами по себе не означают, что он установлен.

## Архитектура

- `ios/DreyzeStore` — приложение SwiftUI с минимальной версией iOS 16.0, типизированным async API-клиентом, пагинацией каталога и поиска, кэшем метаданных и изображений, offline fallback, подробностями приложений и протоколом установки с учётом возможностей устройства.
- `backend` — Cloudflare Worker на TypeScript и Hono, локальные миграции D1 и привязки R2 для будущих публичных ресурсов и приватной временной загрузки. Краткое описание включено в каталог, поэтому карточкам не нужно отдельно запрашивать детали каждого приложения.
- `admin` — статическая панель на React, TypeScript и Vite. В PHASE 1 она проверяет доступность API; аутентификация и изменение данных появятся позднее.
- `shared` — JSON Schema репозитория v1 и общие API DTO.
- `.github/workflows/ci.yml` — проверки backend и admin на Linux, сборка и тесты iOS Simulator на macOS.

Подробности: [архитектура](docs/architecture.md), [iOS-клиент](docs/ios-client.md), [разработка backend](docs/backend.md), [справочник API](docs/api.md), [формат репозитория](docs/repository-format.md), [границы установки](docs/installation.md), [безопасность](docs/security.md), [лицензии](docs/licenses.md), [CI](docs/ci.md) и [развёртывание](docs/deployment.md).

## Скриншоты

Нативный клиент включает Today, Apps, Search, подробности приложения с галереей и историей версий, Updates, Library и Settings. Отображаются только метаданные, полученные от настроенного API. Скриншоты работающего приложения добавим после проверки в симуляторе.

## Требования

- Node.js 22.12 или новее и npm.
- Python 3 для локальной проверки миграций D1.
- macOS и Xcode для сборки iOS и запуска XCTest.
- Для локальной разработки API аккаунт Cloudflare не нужен. Настройка проекта и CI не создают production-ресурсы.

## Сборка iOS-клиента

Откройте `ios/DreyzeStore/DreyzeStore.xcodeproj` в Xcode или выполните на macOS:

```sh
xcodebuild test \
  -project ios/DreyzeStore/DreyzeStore.xcodeproj \
  -scheme DreyzeStore \
  -destination 'platform=iOS Simulator,name=<available iPhone>' \
  CODE_SIGNING_ALLOWED=NO
```

В Debug-конфигурации указан локальный Worker: `http://127.0.0.1:8787/api/v1`. Для другого dev-сервера задайте build setting Xcode `DREYZE_API_BASE_URL`. Release-конфигурация пока использует зарезервированный домен `.invalid`, пока не будет утверждён production endpoint. Mock-каталог не встраивается в приложение.

## Локальный запуск backend

Из корня репозитория:

```sh
npm ci
npm run db:migrate:local
npm run db:seed:local
npm run dev:api
```

Worker обслуживает публичный API под `/api/v1/`: список, детали и версии приложений, категории, подборки, серверный поиск, проверку обновлений, генерацию repository-v1 и health check. Примеры запросов и ответов описаны в [docs/api.md](docs/api.md). Локальный seed содержит только вымышленные метаданные и URL с зарезервированной зоной `.invalid`; IPA-файлов нет. Wrangler использует локальную эмуляцию D1 и R2. После запуска Worker команда `npm run smoke:api:local` проверяет API против локальной D1 и валидирует JSON репозитория. Для локальной разработки не добавляйте remote-флаги.

## Локальный запуск панели администратора

В другом терминале PowerShell:

```powershell
Copy-Item admin/.env.example admin/.env.local
npm run dev:admin
```

Панель проверяет настроенный API. В ней нет фиктивных приложений, сбора учётных данных или неработающих элементов редактирования. Аутентификация и управление появятся в следующих фазах.

## Настройка Cloudflare

`backend/wrangler.jsonc` содержит placeholder для D1 ID и локальные имена бакетов. Эти значения настраивают локальные привязки Wrangler и не создают облачные ресурсы. Production D1/R2, домены, DNS и секреты не настроены. Перед любыми будущими платными операциями или production-действиями изучите [границы развёртывания](docs/deployment.md) и получите явное разрешение.

## Формат репозитория

Нормативная схема репозитория v1 — JSON Schema Draft 2020-12: [shared/schemas/repository-v1.schema.json](shared/schemas/repository-v1.schema.json). Она строго проверяет HTTPS URL без учётных данных, UTC-метки времени, reverse-DNS идентификаторы, версию и build, минимальную версию ОС, метаданные скриншотов, размер пакета и SHA-256 в нижнем регистре. Runtime-валидатор дополнительно проверяет дублирующиеся идентификаторы. Тестовые метаданные используются только в тестах и не выдаются как каталог.

## Backend установки

В приложении пока определён только протокол `InstallationBackend`. Интеграций с TrollStore, TrollStore Lite, Developer Signing, маркетплейсами или внешними установщиками пока нет; exploit-код не добавлялся. См. [документацию по установке](docs/installation.md) о фактическом статусе и ограничениях платформы.

## Безопасность

См. [SECURITY.md](SECURITY.md) и [docs/security.md](docs/security.md). Не добавляйте в Git учётные данные, файлы `.env`, IPA/TIPA, ключи подписи или production-конфигурацию. Совпадение checksum подтверждает целостность файла относительно опубликованного хеша, но не безопасность приложения или его издателя.
