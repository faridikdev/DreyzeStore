# DreyzeStore

[English](README.md) · **Русский**

DreyzeStore — открытая основа для нативного каталога приложений iOS, API метаданных пакетов, формата репозиториев и веб-панели администратора. Проект развивается поэтапно. **Сейчас реализована только инфраструктура PHASE 1, а не готовый магазин:** API каталога, вход администратора и управление приложениями, загрузки, проверка IPA, адаптеры установки и production-развёртывание ещё не реализованы.

Обычное приложение iOS в песочнице, как правило, не может устанавливать произвольные IPA или перечислять все установленные приложения. Клиент будет сообщать об установке только после подтверждения реально доступного backend. Загрузка и проверка пакета сами по себе не означают, что он установлен.

## Архитектура

- `ios/DreyzeStore` — приложение SwiftUI с минимальной версией iOS 16.0, асинхронным API-клиентом на `URLSession`, типизированными моделями и протоколом установки с учётом возможностей устройства.
- `backend` — Cloudflare Worker на TypeScript и Hono, локальные миграции D1 и привязки R2 для будущих публичных ресурсов и приватной временной загрузки.
- `admin` — статическая панель на React, TypeScript и Vite. В PHASE 1 она проверяет доступность API; аутентификация и изменение данных появятся позднее.
- `shared` — JSON Schema репозитория v1 и общие API DTO.
- `.github/workflows/ci.yml` — проверки backend и admin на Linux, сборка и тесты iOS Simulator на macOS.

Подробности: [архитектура](docs/architecture.md), [разработка backend](docs/backend.md), [формат репозитория](docs/repository-format.md), [границы установки](docs/installation.md), [безопасность](docs/security.md), [лицензии](docs/licenses.md), [CI](docs/ci.md) и [развёртывание](docs/deployment.md).

## Скриншоты

Скриншоты появятся после реализации нативных экранов каталога. Текущие экраны iOS явно показывают, что пока не подключены к содержимому магазина.

## Требования

- Node.js 22.12 или новее и npm.
- Python 3 для локальной проверки миграций D1.
- macOS и Xcode для сборки iOS и запуска XCTest.
- Для локальной разработки API аккаунт Cloudflare не нужен. Настройка проекта и CI не создают production-ресурсы.

## Сборка iOS-клиента

Откройте `ios/DreyzeStore/DreyzeStore.xcodeproj` в Xcode или выполните на macOS:

```sh
xcodebuild test \
  -project ios/DreyzeStore/DreyzeStore.xcodeproj \
  -scheme DreyzeStore \
  -destination 'platform=iOS Simulator,name=<available iPhone>' \
  CODE_SIGNING_ALLOWED=NO
```

Настроенный URL API заканчивается на зарезервированном домене `.invalid`, пока будущая конфигурация окружения не задаст конечную точку. Демокаталог не встраивается в приложение.

## Локальный запуск backend

Из корня репозитория:

```sh
npm ci
npm run db:migrate:local
npm run dev:api
```

На этом этапе реализован только `GET /api/v1/health`: он проверяет локальную привязку D1. Маршруты каталога намеренно отвечают `404`, пока не реализованы в соответствующей фазе. Wrangler использует локальную эмуляцию D1 и R2. Для локальной разработки не добавляйте remote-флаги.

## Локальный запуск панели администратора

В другом терминале PowerShell:

```powershell
Copy-Item admin/.env.example admin/.env.local
npm run dev:admin
```

Панель проверяет настроенный API. В ней нет фиктивных приложений, сбора учётных данных или неработающих элементов редактирования. Аутентификация и управление появятся в следующих фазах.

## Настройка Cloudflare

`backend/wrangler.jsonc` содержит placeholder для D1 ID и локальные имена бакетов. Эти значения настраивают локальные привязки Wrangler и не создают облачные ресурсы. Production D1/R2, домены, DNS и секреты не настроены. Перед любыми будущими платными операциями или production-действиями изучите [границы развёртывания](docs/deployment.md) и получите явное разрешение.

## Формат репозитория

Нормативная схема репозитория v1 — JSON Schema Draft 2020-12: [shared/schemas/repository-v1.schema.json](shared/schemas/repository-v1.schema.json). Она строго проверяет HTTPS URL без учётных данных, UTC-метки времени, reverse-DNS идентификаторы, версию и build, минимальную версию ОС, метаданные скриншотов, размер пакета и SHA-256 в нижнем регистре. Runtime-валидатор дополнительно проверяет дублирующиеся идентификаторы. Тестовые метаданные используются только в тестах и не выдаются как каталог.

## Backend установки

В приложении пока определён только протокол `InstallationBackend`. В PHASE 1 нет интеграций с TrollStore, TrollStore Lite, Developer Signing, маркетплейсами или внешними установщиками; exploit-код не добавлялся. См. [документацию по установке](docs/installation.md) о фактическом статусе и ограничениях платформы.

## Безопасность

См. [SECURITY.md](SECURITY.md) и [docs/security.md](docs/security.md). Не добавляйте в Git учётные данные, файлы `.env`, IPA/TIPA, ключи подписи или production-конфигурацию. Совпадение checksum подтверждает целостность файла относительно опубликованного хеша, но не безопасность приложения или его издателя.

## Участие в разработке

Следуйте описанным фазам и делайте изменения удобными для проверки. Запускайте `npm run check`, проверяйте миграции и выполняйте Xcode test scheme на macOS при изменениях iOS-клиента. Не описывайте незавершённые маршруты и установку как работающие функции. См. [процесс разработки](docs/developer-workflow.md).
